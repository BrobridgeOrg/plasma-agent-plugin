# v0.30.0

- 出報表與建立 view（進階模式）：知識沒說的地方，agent 先用 `read_knowledge` 與 `read_schema` 找事實、依事實推測補上，把 SQL 做出來，不再逐洞先問使用者。
- 每一筆推測都列給使用者核對，分兩段：「需要你核對的」（知識庫缺什麼、補成什麼、依據、不對時結果哪裡會變）與「我自己決定的」（欄名、排序、呈現這類不改變定義的選擇）。一次性報表隨結果交出；要建立 mview、pview 或 BI 時在建立前給，使用者核對完才建立。
- 仍然先問的情況：幾個讀法都說得通而事實分不出來、找不到任何依據、被資料推翻的關聯（`relation_refuted`）、mview 要不要固定截點。
- 推測在使用者核對前不寫回知識庫：`submit_answer`、`accept_relationship`、`complete_relationship` 只在使用者說對之後呼叫。
- `compile_query` 的 `answers` 與 `bind` 的 `answer` 寫這一筆補的依據：使用者說的照錄原話，推測的以「代理推測：」開頭。需要同版的 Ophion（分支 `feat/consumer-assume-then-review` 的 `52a7357f` 以後）：`compile_query` 的說明與 `reading` 不再把補上的內容一律稱為使用者的回答（標題是「補上的內容」）。
- 一般模式的做法不變：它原本就是候選推導先驗證、假設納入建立前的摘要、使用者接受後才建立。
