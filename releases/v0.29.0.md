# v0.29.0

- 名稱屬於整個知識庫：概念是 `exp.derived.<短名>`，規則是 `exp.r<序號>`，都不帶文件。知識庫已有的概念用短名或全名直接讀，不用宣告；別份文件已宣告的名稱再宣告會被拒，改讀現有的概念或換一個名稱。
- 產物各自獨立：一次呼叫收下的幾個產物各有 ID，各自以 `revise_rule`、`delete_knowledge` 修改或拿掉。`revise_rule` 改這份工作收下的規則時保留 ID，出處換成這次引用的行；拿掉規則時它宣告的概念留著；還有別的產物在讀的概念、實體型別或規則拿掉會被拒，回覆列出讀它的產物。同一筆註記、關聯、線索或事實寫在兩處，是一個產物帶兩個出處。`report_gap` 回覆 `gap_id`；`finish_document` 以 `drop_changes` 撤回修改後，失去產物的行列在 `uncited_lines`。
- 待補：代理回報的缺口是 `reported-gap:…` 項目，帶 `references`（在等的引用）與 `rules`（點名的規則）；沒有缺口在等的引用自成一個 `gap:…` 項目。`resume_item` 收待補項目或任何產物的 ID，可帶 `document`；回覆的 `products` 每項附 `id`、`kind`、`version`、`lines`、`summary`；產物分屬幾份文件時回 `opened: false` 與 `documents`，什麼都不開，改用要動的產物 ID 再呼叫。修補報告列 `kept_related`。
- 翻譯：`read_translation` 的概念段是依行號排列的一張清單，每項的 `id` 是產物 ID；以 `lines`、`ids`、`section` 篩選。對應段每一組帶 `item_id`（`mapping:<doc_id>`）。
- 使用者指正翻譯：還在 Commit 區的產物以 `resume_item` 帶它的 ID 與 `correction` 重開所屬文件修改；已發布的規則照舊以回答文件修改（`submit_answer` 不帶 `item_id`，再 `revise_rule` 引用回答的行）；對應段以 `resume_item` 帶 `mapping:<doc_id>` 與 `correction`。
- 同一條規則在文件別的行又說一次時，在那幾行再送一次：保留原本的 ID，多一個出處。`delete_knowledge` 的 `kind` 增加 `entity_type` 與 `note`。概念沒有定義的缺口：概念自己的文件寫了定義就 `resume_item` 開那份文件補，使用者說的定義寫在回答文件。
- 查知識庫（進階模式）：`read_schema` 的回覆沒有 `calculated`，不再有計算欄；由欄位算出來的值以 `read_knowledge` 的 `usage` 查讀到它的規則。
- 需要同版的 Ophion（分支 `feat/fragmentless-extraction` 的 `2262b5d5` 以後）：新版知識服務沒有 `fragment:` ID，`read_translation` 也沒有 `fragment_id`。
