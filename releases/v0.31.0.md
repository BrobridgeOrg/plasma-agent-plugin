# v0.31.0

- 文件分析（進階模式）：原文說某個既有欄位是由其他欄位算出來的（例：客戶表的 `total` 是該客戶所有訂單 `cost` 的加總），以 `submit_backbone` 的 `column_derivation` 提交：`subject` 是那一欄，`expression` 是運算式，別張表的欄位經關聯讀（`關聯名稱.欄位`，到多列的關聯放在彙總裡）。系統抽樣檢查資料是否符合，和其他產物一樣在 Commit 頁發布。業務上這個值怎麼算仍用 `submit_node`。
- 查知識（進階模式）：`read_schema` 讀單一欄位時，附註多一種 `column_derivation`：這一欄怎麼由其他欄位算出（`expression`），以及資料檢查的結果（`state`：`verified`、`unverified`、`awaiting_choice`、`refuted`）。回答時連同狀態一起說。
- 需要同版的 Ophion（分支 `feat/column-derivation`）：`submit_backbone` 的 `kind` 多了 `column_derivation`，`read_schema` 的回覆多了這種附註。
