# v0.24.0

- 文件分析：概念宣告不再帶表或欄位。原文對某一欄的說明用 `submit_annotation` 的 `column_words`（它叫什麼、存什麼）與既有的單位、讀法等註記；業務概念用 `record_clue` 記下原文點名的欄位，由 mapping 接到資料。每一欄的儲存概念由程式從 schema 建立。
- 原文說某個值只在某條件下才算時，把「記錄的值」另開一個概念，再寫規則由它得出原概念；後到的文件替既有概念加條件也這樣寫。這條規則會等記錄值對應到資料後才生效，期間原概念照舊有資料。
- mapping：欄位可用 `table` 加 `column` 或用 `stored`（`exp.derived.stored.<db>.<table>.<column>`）指名，兩者是同一筆對應；節點讀的是實體的概念，要用某一欄的值先宣告對應葉子。
- 表或欄位不在 schema 裡時 mapping 記成 `no_source`，文件的片段不用重做。讀法陳述綁定後不用再逐欄寫轉換規則。
- 文字欄對到日期或時間的概念：欄位有自己的讀法時自動轉換；否則在 `read` 引用涵蓋它的讀法通則；都沒有時記成 `format_unknown`。
- 需要 Ophion 0669d3ed 以後（schema 匯入時建立儲存概念，設計 2026-11-11）。
