# v0.37.0

- 文件分析（進階模式）改成無狀態，與舊版不相容：
  - 文件不用開啟或結束，沒有工作與 `work_id`。每種產物一個提交工具，產物以 `upload_id` 指名文件，被接受當下就進 Commit 區；被擋下的提交整筆不留，照回覆處理後重送。
  - 不必寫成知識的行不用記錄，維持未覆蓋；`document_coverage` 隨時列出一份文件已覆蓋與未覆蓋的行。
  - 對應不再自動執行：分析完由代理請使用者決定是否執行 `run_mapping`。沒有對應也能發布，概念列為缺口。
  - 文件改版：`document_coverage` 列出與前一版的差異（`diff`）與待重新確認的已發布產物（`to_reconfirm`），代理逐筆重送、改寫、保留或撤回；處理前它們維持已發布。
  - 兩份文件定義不同而並存時，在 Commit 頁等使用者裁決；裁決前只有牽涉的產物不發布。
  - 多份文件由多個子代理同時分析，各自只帶自己那份的 `upload_id`。
- 補齊缺口：在說明所缺內容的那份文件上提交產物就補上，不用另外開啟項目；使用者的回答先以 `submit_answer` 存成回答文件再引用。新增 `reconfirm:` 待補項目。
- 重新對應：每種對應一個工具（`map_*`），呼叫不再帶 `work_id`。
- skill 只寫流程，以及和使用者之間的事。有哪些產物、各用哪個工具、內容與出處怎麼寫，代理一律從 MCP 的工具說明與 `read_task` 的協定讀。`plasma-document-analysis` 由 19,601 字縮為 7,188 字，`plasma-fill-gaps` 由 9,845 字縮為 4,977 字。
- 已移除、skill 不再使用的工具：`open_document`、`finish_document`、`resume_item`、`document_status`、`submit_rules`、`submit_node`、`submit_annotation`、`submit_backbone`、`submit_metadata`、`submit_group`、`record_clue`、`record_description`、`report_gap`、`declare_reference`、`identify_document`、`revise_rule`、`keep_rule`、`delete_knowledge`、`mapping_submit_mapping`、`mapping_submit_node`、`mapping_record_unmapped`。
- 必須與提供新工具的 Ophion 同版一起發布（Ophion PR #260）：舊工具不保留，兩邊版本不一致時，代理會呼叫不存在的工具。
- 升級後，客戶端要重新取得工具清單：重新連線，或重開宿主的 session。宿主還留著舊清單時，代理會看到已移除的工具。
