# v0.34.0

- 資料對應（進階模式）：每一筆對應記成概念與欄位的對應紀錄，欄位以 `table` 加 `column` 指名；`mapping_submit_mapping` 不再有 `stored`，文件分析也不再提「儲存概念」。
- 查詢（進階模式）：
  - 回覆帶 `schema_changed` 時，告訴使用者知識可能過時，並說明可用重新對應更新；重新對應的觸發條件加上這一項。
  - 知識允許一個成員有好幾個值、執行時查詢說某個成員有不只一個值：問使用者每個值都算（`aggregate.each`、`select.each`）還是只取哪一個。
  - 沒有概念對到的欄位，`read_schema` 列出它在 `compile_query` 用的名稱（標示 `stored`）；`select` 的 `columns` 可列鍵欄名稱。
  - 補洞時帶 `fills`、`answers` 與 `compile_id` 即可，不用重送請求。
  - `accept_relationship` 的確認立即生效，下一次 commit 一併記錄；`complete_relationship` 仍進 Commit 區、發布後驗證。
- 文件分析（進階模式）：`submit_rules` 收下時，回覆會列出規則讀到、還沒有規則得出也沒有對應的概念：文件說了的就寫出它，資料存的值交給 mapping，沒說明的留成缺口。
- 需要同版的 Ophion（分支 `feat/three-layer-mapping`，PR BrobridgeOrg/ophion#242）；進階模式的知識分成三層，既有的進階模式 workspace 要重建或重新發布。
