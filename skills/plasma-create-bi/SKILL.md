# 以 pview 產生 BI 報表

資料來源一律是 Plasma pview，BI 只負責呈現。運算與彙總已由
[建立 pview 技能](../plasma-create-pview/SKILL.md) 在 mview 完成；本 skill 不修改 pview／mview，
發現來源不適合時回到該技能處理。

```text
決定來源 pview → 核對粒度與欄位語意 → 沿用或確認輸出路徑（PBIP／HTML）
→ 核對 API 契約與月份切換 → Power BI MCP 建模／驗證＋PBIR 視覺（或 HTML）→ 驗證與交付
```

## 共通規則

- 全程台灣繁體中文；SQL、DAX、M、工具名稱、識別名稱與 URL 保留原樣。
- 先用 `whoami` 核對 workspace；工具或權限不足時依 [連線技能](../plasma-mcp-setup/SKILL.md) 處理。
- 使用 `whoami`、`list_pviews`、`get_pview`、`list_views`、`get_view`、`execute_pview`。
  `execute_pview` 只用於核對欄位、型別與筆數，**不作為 BI 的資料來源或內嵌資料**。
- Power BI 路徑先探查宿主提供的 Power BI MCP。使用者指定 MCP 時，須實際使用其
  建模／驗證能力，不能只手寫檔案卻宣稱用了 MCP。依 [Power BI MCP 工作流程](references/powerbi-mcp.md)
  連線、建模、保存及驗證；工具不存在時明確回報，不自行安裝或默默改成交付 HTML。
- 不建立 access entry、export API 或排程；**BI 讀取使用者在 Plasma 自行建立的資料 API**。
- 資料 API URL 若含存取權杖，視同憑證：不回顯完整 URL、不寫進 skill、版本庫、驗證
  紀錄或可分享摘要。使用者提供 URL 並要求以它建立可連線的本機報表時，可直接呼叫
  該 API 並在指定輸出位置保存必要連線設定；交付提醒該設定含憑證。可提交模板仍用占位值。
- 已提供的來源、路徑、圖表與參數直接沿用；只釐清會影響正確性的缺漏，不逐步重問授權。
  一般配色、版面與欄位擺放由 agent 完成。使用者要求 subagent 時，可委派報表產出，
  主 agent 負責檢查實際檔案與驗證證據；不同 agent 使用各自的明確 MCP connectionName。

## 1. 決定來源 pview

- **接續本 session 的建立流程**：直接使用 `plasma-create-pview` 剛交付的 pview（以其 ID），
  並沿用當時整理的輸出欄位表與參數說明，不再要求使用者指定。
- **沒有前序建立流程**：請使用者提供 pview 名稱。以 `list_pviews(keywords=<名稱>)` 查找，
  只接受名稱完全相符的一筆；沒有相符時列出相近名稱請使用者確認，多筆相符時請使用者選擇。
  不從清單自行挑選、不以 ID 或描述猜測。

以 `get_pview` 讀取 SQL 與 `param_def`，並核對：

1. **來源是 mview**：SQL 的 FROM 路徑對得上 `list_views`／`get_view` 中 `type=materialized_view`
   的 `path`。不是時說明風險並建議回到 `plasma-create-pview`；使用者明確接受才繼續。
2. **核對報表粒度與 pview 完整結果**：以使用者預期的最大參數範圍執行一次
   `execute_pview`（`page_size` 取小值），`total` 須不超過 pview 單次回傳上限
   （未提供時以 1,000 列為假設），且 `truncated=false`。此上限只套用在 pview
   最後篩選後的完整結果，不限制來源 mview 的總列數或歷史範圍；page_size 只控制樣本。
   粒度不適合報表或單次完整結果超限時，回到 `plasma-create-pview` 檢查最後篩選與
   報表需求；不因 mview 超過 1,000 列就要求縮減資料或改變粒度，也不自行限制單月。
   不在 BI 端分頁繞過完整結果上限或加總明細重算指標；驗證工具的樣本分頁另計。
  為前端切換月份而載入多個完整月結果時，依 [日期選擇器](references/date-selection.md)
  區分每次 API 回傳上限與模型累計列數，不能把累計資料量套用單次上限。
3. **欄位語意**：本 session 有欄位表時沿用；沒有時以 `get_view` 讀 mview SQL 判讀。
   將每個欄位分類為「期別」「區塊（如 `section`）」「維度」「可加總量值（分子、分母、次數、總和）」
   「不可加總量值（去重人數、比率、平均、中位數、排名）」。無法判斷的欄位請使用者確認，不猜測。

## 2. 選擇輸出路徑

使用者尚未指定時，**請使用者二選一**（宿主有提問工具時使用）：

| 路徑 | 產出 | 適合 |
|---|---|---|
| **1. Power BI（PBIP）** | Power BI Desktop 專案資料夾：TMDL 語意模型、PBIR 報表、Power Query 參數 | 已使用 Power BI、要發布到 Power BI Service |
| **2. HTML BI** | 單一 `.html` 檔：參數表單、KPI 卡片與圖表，瀏覽器直接開啟 | 不需安裝軟體、快速分享或嵌入 |

不替使用者決定；使用者要求兩種都做時依序完成。

## 3. 規劃報表

依使用者提供的規格（截圖、既有報表、文字描述）及前序 pview 欄位表規劃。
規格足夠時直接完成下列配置；只有指標、參數或必要視覺有互斥解讀時才集中釐清：

- 視覺清單：每個視覺的類型（KPI 卡片、長條圖、折線圖、圓餅圖、表格等；PBIP 路徑只用
  [PBIP 格式](references/pbip.md) 視覺表內的類型）、使用的區塊與欄位、
  排序、數值格式（百分比、千分位、小數位、單位）。
  人次、人數與筆數預設顯示完整整數及千分位（如 `6,037`），視覺顯示單位明確設為
  None，不沿用 Auto 的「6 千」。模型 `formatString` 不能取代視覺層的顯示單位設定。
- 報表文案以讀者理解指標為準：標題、標籤、圖例與軸標題用業務名稱，移除自動顯示的
  英文量值／欄位名。SQL 條件、去重鍵、`seq_num=1`、資料表或欄位識別名稱放在
  交付說明，不直接綁定來源 `data_note` 到卡片。需要提示缺資料時，只呈現簡短的
  業務說明；使用者要求移除的技術文案須從所有頁面、標籤與 tooltip 一併移除。
- 參數：pview 的每個 `variable_name` 對應報表上的哪個輸入，型別與預設值；
  單月份 API 參數沿用月初日期；只有起訖區間才註明 `[開始, 結束)`。
  Import 模式的 Power Query 參數須改值後重新整理；一般 slicer 只篩選已載入資料，
  不能把它宣稱成會重新呼叫 pview 的月份輸入。
- **日期須能從報表前端選擇**：需要讀者切換日期／月份的報表，提供可見的日期選擇器，
  不以「轉換資料 → 編輯參數」代替前端操作。依 [日期選擇器](references/date-selection.md)
  設計資料載入範圍、日期維度及所有圖表的篩選傳遞。來源只有月彙總時提供月份單選，
  不宣稱支援任意日區間。區分「選日期看哪期」與「重新整理取得最新值」，清楚說明
  目前連線能否依選取即時查 API；不能將連接器限制說成 MCP 缺少操作。
- 視覺與欄位對照依下列規則，不另外發明運算：
  - 視覺直接呈現 pview 回傳的值；BI 端只允許篩選區塊、排序與格式化。
  - 需要跨列合計時，只能加總可加總量值，比率以「分子合計 ÷ 分母合計」計算。
  - 不可加總量值只在篩選後恰好一列時顯示；多列時顯示空白並註明，
    **不做 SUM、AVERAGE 或加權**。
  - 維度類別的 Top N、「其他」等呈現規則已在 mview 決定，BI 不再截斷或重新分組。

## 4. 確認資料 API

1. 沿用使用者已提供的資料 API URL；缺少時才詢問。本 skill 不代建資料 API。
2. 核對 API 的 HTTP 方法、參數位置與編碼如何對應 pview 的 `variable_name`。
   不假設一定是同名 URL query string；以實際成功回應與參數變更效果確認契約。
3. **確認實際回應格式**：在已授權的報表工作中，以代表性參數唯讀呼叫 API，記錄
   最上層結構、欄位、型別、分頁／截斷標記及錯誤回應。至少測預設月份與另一個已知
   有不同結果的月份，核對回傳期別及指標確實改變；HTTP 200 不代表參數生效。
   不憑 `execute_pview` 的回應形狀猜測 API 格式。記錄僅保留結構與必要彙總，不含權杖。
4. API 完整結果列數不超過上限且一次取得完整結果才繼續；需要分頁才能取完時回到
   第 1 節第 2 點。此處指正式資料 API，不是 `execute_pview` 的驗證樣本分頁。

## 5. 產生檔案

- **路徑 1**：依 [Power BI MCP 工作流程](references/powerbi-mcp.md) 建立／驗證模型，
  依 [PBIP 格式](references/pbip.md) 補齊報表。MCP 的語意模型匯出不是完整 PBIP，
  必須另有 `.pbip`、報表引用、頁面與視覺。檔案格式以參考文件及實際工具 schema 為準。
- **路徑 2**：依 [HTML BI 格式](references/html.md) 產生單一 HTML 檔。

**產生的檔案不寫任何註解**：HTML 不用 `<!-- -->`，CSS、JavaScript、DAX、M 不用 `//`、`/* */`，
TMDL 不用 `///` 描述。

輸出位置使用使用者指定的目錄；未指定時放在目前工作目錄，以報表名稱命名。
目標已存在時先查看內容，避免覆寫無關檔案；本次產物的修正與重建沿用既有授權。
需要取代使用者既有且未授權覆寫的報表時，再確認具體檔案。

## 6. 驗證與交付

驗證能在本機完成的部分，無法驗證的項目如實列出，不宣稱已在 Power BI Desktop 或瀏覽器中測試：

- **PBIP**：所有 JSON 可解析且 `$schema` 正確；TMDL 以 Tab 縮排、UTF-8 無 BOM；
  視覺引用的資料表、欄位、量值名稱都存在於 TMDL；資料夾與物件名稱只含英數、底線、連字號。
  透過 MCP 重新載入保存後模型並核對物件；有本次報表的可用 Desktop 執行個體時，
  完成刷新與 DAX 數值比對。離線模型或登入介面限制時，完成能做的驗證後具體回報
  未驗證項目，不一律把所有驗證交給使用者，也不把離線解析成功說成刷新成功。
  有桌面操作工具時依其技能截取實際報表，逐頁檢查長標題、月份、最大數值、類別名稱、
  卡片內部標籤與軸標題，修正遮擋、截字及非預期捲軸後再截圖確認。外框未重疊與
  schema 通過都不能證明文字可讀；卡片要留足內距，避免標題與自動標籤重複佔空間。
  有日期選擇器時，實際從前端切換至少兩期，確認所有 KPI、圖表、標題同步改變，
  再切回預設期別保存；只執行帶日期篩選的 DAX 不代表選擇器互動已驗證。
- **HTML**：以本機可用工具檢查 JavaScript 語法；用第 4 節取得的回應範例驗證解析與繪圖邏輯
  （透過頁面的匯入 JSON 功能，不把資料寫死在檔案）。

交付時列出：

- 來源 pview 名稱與 ID、其讀取的 mview、workspace。
- 產生的檔案樹與開啟方式。
- Power BI MCP 實際完成的操作、API／檔案／模型／刷新／視覺各層的驗證結果；
  沒有 Desktop 實際渲染證據時，不宣稱已確認圖表畫面。
- 視覺對照表：

  | 視覺 | 類型 | 區塊／欄位 | 計算方式 | 格式 |
  |---|---|---|---|---|
  | Total Admissions | KPI 卡片 | `kpi`／`total_admissions` | 單列直接顯示 | `#,0` |

- 參數與 API 實際傳參方式的對應；單月填月初日期，起訖區間才說明結束日不含。
- 不可加總指標的限制、API 權杖處理方式，以及使用者尚需完成的步驟
  （例如 Power BI 填參數、設定匿名認證並重新整理；HTML 填入 API URL）。
