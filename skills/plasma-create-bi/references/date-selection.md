# 前端日期與月份選擇

讀者應在報表頁面選日期／月份。Power Query 載入參數是資料管理設定，不能把它當成
前端日期控制項交付。實作前區分來源粒度、顯示期別與資料新鮮度。

## 選擇互動方式

- **Web API＋Import**：用日期選擇器篩選已載入的多期資料。切換月份不重新呼叫 API；
  原始資料更新並同步 mview 後，Power BI 仍須重新整理才取得更新值。
- **支援的 DirectQuery 來源**：可評估動態 M 參數，讓選取值傳入來源查詢。須實測
  連接器與型別支援，不能只改模型模式或增加 MCP 操作便宣稱普通 Web API 可用。
- 使用者明確要求「選日期就呼叫 API」時，先核對來源是否支援所需連線；不默默替換成
  預載資料，也不將目前 Web＋Import 的限制擴大成 Power BI 所有方式均不可能。

依據：[動態 M 參數](https://learn.microsoft.com/en-us/power-bi/connect-data/desktop-dynamic-m-query-parameters)、
[Web 連接器](https://learn.microsoft.com/en-us/power-query/connectors/web/web)。能力有版本差異時重新查核。

## Import 資料載入

1. 明確列出前端可選範圍、預設期別及更新方式，沿用使用者指定範圍。尚未指定時先提出
   合理範圍，不擅自載入全部歷史或把本次年月寫成永遠不可變的範圍。
2. API 已支援多期就核對完整結果；API 只回單月時，可為約定的多月瀏覽範圍，逐月
   呼叫並保留每月完整結果。每次均須核對期別、欄位、錯誤與截斷；某月失敗不能吞成
   空表。這與分頁補取一個被截斷的結果不同，不容許用分頁掩蓋單次結果超限。
3. 1,000 列限制適用 pview 每次完整回傳，不適用 Power BI 已載入的多次完整結果合計，
   也不適用 mview 儲存量。不得因此截斷模型或把多月值混合重算。
4. 可增加 `LoadStartMonth`／`LoadEndMonth` 等載入範圍參數，與 API 的單月參數分開命名；
   這些不是讀者的前端月份選單，也不改 API 契約。核對起訖及是否含結束月。
5. 估算 API 呼叫量與刷新成本。Power Query 共用查詢／`Table.Buffer` 不保證跨表只執行
   一次；避免為月份維度再呼叫全部 API。大範圍先評估單一載入表或適合的來源連線。

## 模型與前端

- 建立一列一期的日期／月份維度，以日期鍵關聯到每個指標、分類與排行資料表；關聯
  由維度單向篩選資料表，不能只讓月份篩選其中一張表。
- 月報可提供 `yyyy年MM月` 單選下拉式選單，以實際月初日期排序；預設選使用者指定月份。
  不提供沒有月度定義支援的任意日區間，也不讓平均、去重指標或每月 Top 10 混成多月。
  原生 `slicer` 的角色為 `Values`；下拉模式用 `objects.data[].properties.mode='Dropdown'`。
  依當次 schema／Desktop 輸出核對 `selection.strictSingleSelect=true`、
  `selectAllCheckboxEnabled=false`；`selection.singleSelect` 可能控制的是「以 CTRL 多選」，
  不能單靠它保證單選。預設值設在 slicer 自身的選取條件，不加固定月份 page filter，
  否則下拉選單可能只剩預設月份。語法值仍依 PBIR Literal 格式編碼。
- 除來源單列檢查外，所有月報量值都須確認只有單一月份。否則某些分類在多月中恰有
  一列時仍會錯誤顯示；KPI、圓餅、排行與排名都要保護。
- 日期標題與資料來自同一篩選上下文。清除／多選／無資料時顯示恰當提示或空值，不將
  舊月份數值搭配新月份標題。來源 null 仍保留空白。
- 技術細節留在 README；前端只需清楚的「報表月份」及必要的更新提示。

## 月份查核

核對月份維度關聯、各量值的單月保護、動態標題、slicer 預設值與互動設定，確認
沒有固定月份 page filter 或內嵌資料快照。API 至少測兩個不同月份。
有本次可執行模型且 MCP 支援時，以帶月份篩選的 DAX 比對各 KPI、圖表數值及標題，
並檢查未選單一月份時不會混月；完成後保留使用者指定的預設月份。
離線模型以月份維度、量值及視覺設定的定義查核完成交付。
一般交付只說明可選月份，需使用者刷新時請其開啟後按「重新整理」。
